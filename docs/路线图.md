# RAG 项目路线图

这份文件是项目的「总纲」：记录目标、分期、已完成状态和后续每一期要做什么。  
新开发（或新会话）从这里开始读，再看对应的需求卡。

## 项目目标

用 FastAPI + LangChain 做一个知识库问答服务。接口稳定后：

- **PageIo**（Next.js 博客，`~/Desktop/PageIo`）加「AI 问答」入口，做流式问答
- **local-agent**（Electron Agent，`~/Desktop/local-agent`）新增 tool，调同一套 API

本仓只做 RAG 服务本体（+ 可选调试前端），不把 LangChain 塞进上面两个项目。

## P2：检索 + 非流式问答

### 一句话需求

用户提一个问题，系统从 `chunks` 里找出最相关的几块，拼进 prompt 交给 DeepSeek，返回答案和引用来源。

### 做

- 检索服务：把问题向量化，用 pgvector 余弦距离取 Top-K（默认 5）
- prompt 组装：系统提示 + 检索到的片段 + 用户问题
- `POST /chat`：非流式，返回 `answer` + `citations`
- `citations` 里带 `document_id`、`document_title`、`chunk_index`、`content` 片段、相似度得分
- 可选：`GET /search` 只做检索不调 LLM（调试用，很推荐先做这个）

### 不做

- 流式输出（P3）
- 会话历史、多轮追问（P3）
- 重排序（rerank）、混合检索（关键词 + 向量）
- Agent / 工具调用

### 技术要点

余弦距离用 pgvector 的 `<=>` 运算符，SQLAlchemy 里写成：

```python
Chunk.embedding.cosine_distance(query_vector)
```

距离越小越相似，相似度可用 `1 - distance` 表示。查询大致是：

```python
select(Chunk, Chunk.embedding.cosine_distance(qv).label("distance"))
    .order_by("distance")
    .limit(top_k)
```

需要 join `documents` 拿标题，且只查 `status='ready'` 的文档。

LLM 调用用 `langchain-openai` 的 `ChatOpenAI`，`base_url` 指向 DeepSeek，模型 `deepseek-chat`。

### 成功标准

- [ ] 入库一篇文档后，`POST /chat` 能基于该文档内容回答
- [ ] 返回的 `citations` 能对上原文块
- [ ] 库里没有相关内容时，回答里明确说「资料里没提到」而不是瞎编
- [ ] 未配置 LLM key 时返回 503

### 边界

| 场景 | 预期 |
|------|------|
| 库里一条数据都没有 | 返回提示「知识库为空」，不调 LLM |
| 检索结果相似度都很低 | 仍可调 LLM，但 prompt 里要求它承认不知道 |
| LLM 超时 | 502 并带原因 |

## P3：流式输出 + 会话历史

### 一句话需求

前端能像 ChatGPT 那样逐字看到回答，并且支持多轮追问。

### 做

- `conversations` / `messages` 两张表（设计见下）
- `POST /chat/stream`：SSE（`text/event-stream`）逐 token 推送
- 事件协议约定（建议）：
  - `event: citations` — 开头先把引用发过去
  - `event: token` — 每个片段
  - `event: done` — 结束，带完整答案和 message_id
  - `event: error` — 出错
- 多轮：把最近 N 轮对话拼进 prompt
- `GET /conversations/{id}` 拉取历史

### 表设计

**conversations**：`id`、`title`、`client`（`web` / `pageio` / `local-agent`）、`external_uid`（可选，对端用户标识）、`created_at`

**messages**：`id`、`conversation_id`（外键）、`role`（`user` / `assistant` / `system`）、`content`、`citations`（JSONB）、`created_at`

### 技术要点

FastAPI 用 `StreamingResponse` + 异步生成器；LangChain 侧用 `astream`。  
注意 SSE 每条消息格式是 `data: xxx\n\n`，且要设 `Cache-Control: no-cache`。  
Nginx 反代时需要关掉缓冲（`proxy_buffering off`），否则流式会被攒成一坨。

### 成功标准

- [ ] `curl -N` 能看到逐步输出而不是一次性返回
- [ ] 刷新页面后能通过 `GET /conversations/{id}` 还原历史
- [ ] 追问「刚才说的那个是什么意思」能理解上下文

## P4：接入 PageIo / local-agent

### 做

- **鉴权**：给调用方发 token（简单方案：`.env` 里配一个服务端 API Key，请求带 `Authorization` 头）
- **PageIo 接入**：博客前端加问答入口，fetch SSE 调 `/chat/stream`
- **博客同步**（可选但推荐）：
  - PageIo 发布 / 更新文章时 POST 到 RAG，`source_type='blog'`、`source_uri=blog id`
  - RAG 侧去掉 HTML 标签再切块（正文是 HTML LONGTEXT）
  - 同一篇博客重复同步要幂等（按 `source_type + source_uri` 查找已有文档并覆盖）
- **local-agent 接入**：主进程加 tool `rag_search` / `rag_chat`，HTTP 调本服务

### 现有系统信息（别改错库）

| 项目 | 技术 | 数据库 |
|------|------|--------|
| PageIo | Next.js 14 + Express（:3002） | MySQL `blog_db`（`users`、`blogs`） |
| local-agent | Electron + React + OpenAI SDK | 无 |
| 本项目 | FastAPI（:8000） | Postgres `rag_db` |

`blogs` 表关键字段：`id`（varchar）、`title`、`content`（HTML）、`status`（`published`/`hidden`/`draft`）、`user_id`。只同步 `published`。

另外本机 Postgres 里还有一个 `langchain_db`，是 LangGraph checkpoint 学习库，**不要动**。

### 部署备忘

代码放 `/opt/rag`，配置放 `/etc/rag/rag.env`（`chmod 600`），systemd 用 `EnvironmentFile` 注入，nginx 反代加 HTTPS 并关闭 `proxy_buffering`。

## 开发约定

1. 每期先填需求卡（模板见 `需求卡-模板与P0.md`），明确「做 / 不做 / 验收标准」
2. 开分支 `feat/pX-xxx`，验收项全过再合并 main
3. 密钥只进 `.env`（已 gitignore），示例值写进 `.env.example`
4. 错误码统一：400 参数、404 不存在、502 外部服务失败、503 依赖未配置
