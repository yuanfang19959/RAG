# RAG 项目路线图

这份文件是项目的「总纲」：记录目标、分期、已完成状态和后续每一期要做什么。  
新开发（或新会话）从这里开始读，再看对应的需求卡。

## 项目目标

用 FastAPI + LangChain 做一个知识库问答服务。接口稳定后：

- **PageIo**（Next.js 博客，`~/Desktop/PageIo`）加「AI 问答」入口，做流式问答
- **local-agent**（Electron Agent，`~/Desktop/local-agent`）新增 tool，调同一套 API

本仓只做 RAG 服务本体（+ 可选调试前端），不把 LangChain 塞进上面两个项目。

## P2：检索 + 非流式问答（已完成）

实现落在 `services/retrieval.py`（向量检索）、`services/llm.py`（DeepSeek 客户端）、
`services/chat.py`（prompt 与编排）、`api/chat.py`（`/search`、`/chat`）。
下面是当初的需求记录，保留备查。

### 一句话需求

用户提一个问题，系统从 `chunks` 里找出最相关的几块，拼进 prompt 交给 DeepSeek，返回答案和引用来源。

### 做

- 检索服务：把问题向量化，用 pgvector 余弦距离取 Top-K（默认 5）
- prompt 组装：系统提示 + 检索到的片段 + 用户问题
- `POST /chat`：非流式，返回 `answer` + `citations`
- `citations` 里带 `document_id`、`document_title`、`chunk_index`、`content` 片段、相似度得分
- 可选：`GET /search` 只做检索不调 LLM（调试用，很推荐先做这个）

### 不做

- 流式输出（P3）
- 会话历史、多轮追问（P3）
- 重排序（rerank）、混合检索（关键词 + 向量）
- Agent / 工具调用

### 技术要点

余弦距离用 pgvector 的 `<=>` 运算符，SQLAlchemy 里写成：

```python
Chunk.embedding.cosine_distance(query_vector)
```

距离越小越相似，相似度可用 `1 - distance` 表示。查询大致是：

```python
select(Chunk, Chunk.embedding.cosine_distance(qv).label("distance"))
    .order_by("distance")
    .limit(top_k)
```

需要 join `documents` 拿标题，且只查 `status='ready'` 的文档。

LLM 调用用 `langchain-openai` 的 `ChatOpenAI`，`base_url` 指向 DeepSeek，模型 `deepseek-chat`。

### 成功标准

- [ ] 入库一篇文档后，`POST /chat` 能基于该文档内容回答
- [ ] 返回的 `citations` 能对上原文块
- [ ] 库里没有相关内容时，回答里明确说「资料里没提到」而不是瞎编
- [ ] 未配置 LLM key 时返回 503

### 边界

| 场景 | 预期 |
|------|------|
| 库里一条数据都没有 | 返回提示「知识库为空」，不调 LLM |
| 检索结果相似度都很低 | 仍可调 LLM，但 prompt 里要求它承认不知道 |
| LLM 超时 | 502 并带原因 |

## P3：流式输出 + 会话历史 + 聊天前端（已完成）

实现落在 `api/chat.py`（`/chat/stream`）、`api/conversations.py`、`services/chat.py`
（`build_messages` / `stream_answer`）、`frontend/`（umi + Ant Design X）。
验收与踩坑见 `需求卡-P3.md`，iframe 嵌入见 `嵌入博客.md`。下面是当初的需求记录，保留备查。

### 一句话需求

前端能像 ChatGPT 那样逐字看到回答，并且支持多轮追问。

### 做

- `conversations` / `messages` 两张表（设计见下）
- `POST /chat/stream`：SSE（`text/event-stream`）逐 token 推送
- 事件协议约定（建议）：
  - `event: citations` — 开头先把引用发过去
  - `event: token` — 每个片段
  - `event: done` — 结束，带完整答案和 message_id
  - `event: error` — 出错
- 多轮：把最近 N 轮对话拼进 prompt
- `GET /conversations/{id}` 拉取历史

### 表设计

**conversations**：`id`、`title`、`client`（`web` / `pageio` / `local-agent`）、`external_uid`（可选，对端用户标识）、`created_at`

**messages**：`id`、`conversation_id`（外键）、`role`（`user` / `assistant` / `system`）、`content`、`citations`（JSONB）、`created_at`

### 技术要点

FastAPI 用 `StreamingResponse` + 异步生成器；LangChain 侧用 `astream`。  
注意 SSE 每条消息格式是 `data: xxx\n\n`，且要设 `Cache-Control: no-cache`。  
Nginx 反代时需要关掉缓冲（`proxy_buffering off`），否则流式会被攒成一坨。

### 成功标准

- [x] `curl -N` 能看到逐步输出而不是一次性返回
- [x] 刷新页面后能通过 `GET /conversations/{id}` 还原历史
- [x] 追问「刚才说的那个是什么意思」能理解上下文

### 实际实现与原计划的差异

- 前端超出原计划：加了 umi + Ant Design X 的全页与 iframe 挂件两个页面
- `messages.role` 只用 `user` / `assistant`，system prompt 不入库（每次由代码拼，改 prompt 不用迁移数据）
- 流式生成器里自己开数据库会话，不复用 `Depends(get_session)`（生成器活得比请求久）
- `done` 事件只带 id 和 model，不重复发完整答案（前端自己攒好了）

## P4：接入 PageIo / local-agent

### 待决策：无登录体系下的防滥用（2026-09-12 讨论，方案未定）

**背景：** `/chat/stream` 一旦公开，谁都能调，烧的是 DeepSeek 额度。博客访客大多未登录。

**成本量化**（高峰时段，缓存未命中输入 ¥3/百万 token、输出 ¥9/百万；top_k=5、chunk 500 字，
一次约 3000 输入 + 300 输出 token）：

| 规模 | 成本 |
|------|------|
| 一次问答 | 约 ¥0.01（空闲时段减半） |
| 1 万次 | 约 ¥120 |
| 脚本每秒 1 次刷一天 | 约 ¥1000 |

风险量级是"一顿饭到一个月房租"，取决于多久发现。结论：不值得做精确身份识别，
但必须有硬上限防止整夜被刷。

**关于浏览器指纹（原始提问）：** 能取，但**防不住脚本**。指纹是客户端算好随请求上报的字符串，
攻击者直接 curl 就绕过了，或者抓一次真实指纹无限重放。且挂件在 iframe 内是独立 origin，
FingerprintJS 的 `visitorId` 依赖 localStorage，iframe 内外可能对不上。
**指纹只能当限流的一个维度（提高作弊成本），不能当身份。**

**候选分层方案**（按性价比排序）：

| 层 | 措施 | 定位 |
|----|------|------|
| 0 | DeepSeek 控制台限额：只充够用的钱、不自动续费、开余额告警 | 唯一硬止损，代码再错也烧不超余额 |
| 1 | 服务端全局日配额，超了一律 429 | **最重要**：不依赖识别准不准，换 IP / 伪造指纹都拦得住 |
| 2 | IP 限流（nginx `limit_req` 或应用层） | 门槛从"写 for 循环"提到"买代理池" |
| 3 | Cloudflare Turnstile invisible（免费、挑战无限、无需接 CDN） | 无登录体系下**真正有效**的一层 |
| 4 | cookie 匿名 ID / 指纹做每日次数 | **体验**（提示剩余次数），不是安全 |
| 5 | Origin / Referer 校验 | 免费，挡最低级的，可伪造 |

Turnstile 与指纹的本质区别：指纹是客户端自报；Turnstile 由 Cloudflare 签发、
服务端调 `siteverify` 校验，token 5 分钟有效且单次使用，重放返回 `timeout-or-duplicate`，
攻击者伪造不了。

**另一个选项：** PageIo 已有 JWT 登录（`users` 表），可做分级配额——未登录 5 次/天、
登录 50 次/天。比纯技术手段更像真实产品的取舍。

**天然防护：** system prompt 强制只依据知识库回答，别人没法把接口当免费 ChatGPT 代理用，
这消除了最大的滥用动机。

**顺带记一笔：** `config.py` 里 `llm_model = "deepseek-chat"` 已是 legacy 别名，
DeepSeek 官方建议改成 `deepseek-flash`（现在仍兼容映射，哪天下线会 502）。

### 做

- **鉴权**：给调用方发 token（简单方案：`.env` 里配一个服务端 API Key，请求带 `Authorization` 头）
- **PageIo 接入**：博客前端加问答入口，fetch SSE 调 `/chat/stream`
- **博客同步**（可选但推荐）：
  - PageIo 发布 / 更新文章时 POST 到 RAG，`source_type='blog'`、`source_uri=blog id`
  - RAG 侧去掉 HTML 标签再切块（正文是 HTML LONGTEXT）
  - 同一篇博客重复同步要幂等（按 `source_type + source_uri` 查找已有文档并覆盖）
- **local-agent 接入**：主进程加 tool `rag_search` / `rag_chat`，HTTP 调本服务

### 现有系统信息（别改错库）

| 项目 | 技术 | 数据库 |
|------|------|--------|
| PageIo | Next.js 14 + Express（:3002） | MySQL `blog_db`（`users`、`blogs`） |
| local-agent | Electron + React + OpenAI SDK | 无 |
| 本项目 | FastAPI（:8000） | Postgres `rag_db` |

`blogs` 表关键字段：`id`（varchar）、`title`、`content`（HTML）、`status`（`published`/`hidden`/`draft`）、`user_id`。只同步 `published`。

另外本机 Postgres 里还有一个 `langchain_db`，是 LangGraph checkpoint 学习库，**不要动**。

### 部署备忘（线上实际）

- 与 PageIo 同机；RAG 用 **pm2** 进程名 `rag`，监听 `127.0.0.1:8000`（**安全组不开 8000**）
- Postgres 16 + pgvector，库名 `rag_db`，本机 `trust` 无密码；旧系统 `postgresql.service` 已停以免占 5432
- **Nginx 当前用方案 B**：主域 `www.yuanfang19959.icu` 下反代 `/ui/` 与 `/health|/chat|…` → `:8000`；博客 `/`→`:3000`，`/api/`→`:3002` 不动。细节与配置片段见 `docs/嵌入博客.md`
- 挂件地址：`https://www.yuanfang19959.icu/ui/#/widget`
- 备选方案 A（子域名 `rag.`）尚未采用；SSE 必须 `proxy_buffering off`
