# 把问答挂件嵌进博客（PageIo）

本文只提供可复制的代码，**P3 阶段不改动 PageIo 仓库**。

## 方案

RAG 服务把前端产物挂在自己的 `/ui` 下，博客用 iframe 引这个地址。生产前端 `API_BASE` 为空，接口打在**同源根路径**（`/chat`、`/health`…），所以反代必须同时覆盖 `/ui/` 和这些 API 路径。

### 当前线上：方案 B（主域路径，已采用）

和博客共用 `www.yuanfang19959.icu` 的 HTTPS，Nginx 把指定路径转到本机 `127.0.0.1:8000`。**不开放安全组 8000**，进程用 **pm2**（与 PageIo 一致）。

```
博客页面 (https://www.yuanfang19959.icu)
  └─ iframe src="https://www.yuanfang19959.icu/ui/#/widget"
       └─ iframe 内请求 /chat/stream、/conversations…（同源，不跨域）
            └─ Nginx location → FastAPI :8000
```

挂件环境变量：

```bash
NEXT_PUBLIC_RAG_WIDGET_URL=https://www.yuanfang19959.icu/ui/#/widget
```

在博客 HTTPS 的 `server { ... }` 里，与现有 `location /api/`、`location /` **同级**增加（不要嵌进 `location /`）：

```nginx
    # RAG 前端（umi 产物，publicPath=/ui/）
    location /ui/ {
        proxy_pass http://127.0.0.1:8000/ui/;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_buffering off;
        proxy_read_timeout 3600s;
    }

    # RAG API（勿占用博客已有的 /api/）
    location ~ ^/(health|docs|openapi\.json|redoc|chat|search|documents|conversations) {
        proxy_pass http://127.0.0.1:8000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_buffering off;
        proxy_cache off;
        proxy_read_timeout 3600s;
        proxy_send_timeout 3600s;
    }
```

路径对照（避免改错）：

| 路径 | 指向 |
|------|------|
| `/` | PageIo Next `:3000` |
| `/api/` | PageIo Express `:3002` |
| `/ui/` + 上表 API | RAG FastAPI `:8000` |

注意：博客路由若将来也用 `/chat`、`/documents` 等，会和方案 B 冲突，那时再迁方案 A。

### 备选：方案 A（子域名）

```
博客 → iframe src="https://rag.yuanfang19959.icu/ui/#/widget"
         └─ 整个 rag 子域反代到 :8000（API 也在该子域根路径）
```

需要 DNS `rag` A 记录 + 单独（或 SAN）证书。路径更干净，与博客零冲突；当前未采用。

### 为什么用 iframe

- 博客是 antd 5，Ant Design X 要求 antd 6，同仓会打架
- 聊天应用可以独立部署、独立更新，不用每次都重新发博客
- 样式完全隔离，博客的全局 CSS 不会影响挂件
- 代价是父子页面要靠 `postMessage` 通信，主题色需要手动同步

## 博客侧组件

放在 PageIo 的 `components/RagWidget/index.tsx`：

```tsx
'use client';

import { useEffect, useRef, useState } from 'react';

const WIDGET_SRC = process.env.NEXT_PUBLIC_RAG_WIDGET_URL!;

export default function RagWidget() {
  const [open, setOpen] = useState(false);
  // 首次点击才赋值 src，避免拖慢博客首屏
  const loaded = useRef(false);
  if (open) loaded.current = true;

  useEffect(() => {
    const onMessage = (event: MessageEvent) => {
      // 只认自己那个域发来的消息
      if (new URL(WIDGET_SRC).origin !== event.origin) return;
      if (event.data?.type === 'rag-widget:close') setOpen(false);
    };
    window.addEventListener('message', onMessage);
    return () => window.removeEventListener('message', onMessage);
  }, []);

  return (
    <>
      {loaded.current && (
        <iframe
          title="RAG 问答"
          src={WIDGET_SRC}
          style={{
            position: 'fixed',
            right: 24,
            bottom: 92,
            width: 380,
            height: 560,
            border: 'none',
            borderRadius: 12,
            boxShadow: '0 12px 32px rgba(0,0,0,.18)',
            display: open ? 'block' : 'none',
            background: '#fff',
            zIndex: 1000,
          }}
        />
      )}
      <button
        onClick={() => setOpen((v) => !v)}
        style={{
          position: 'fixed',
          right: 24,
          bottom: 24,
          width: 56,
          height: 56,
          borderRadius: '50%',
          border: 'none',
          background: '#1677ff',
          color: '#fff',
          cursor: 'pointer',
          zIndex: 1001,
        }}
      >
        问
      </button>
    </>
  );
}
```

在 `app/layout.tsx` 里挂一次即可。当前方案 B 的 `.env.local`：

```bash
NEXT_PUBLIC_RAG_WIDGET_URL=https://www.yuanfang19959.icu/ui/#/widget
```

（若改回方案 A，换成 `https://rag.yuanfang19959.icu/ui/#/widget`。）

移动端建议改成全屏：宽高用 `100vw` / `100dvh`，`right/bottom` 归零。

## 服务端要注意的

**1. 允许被博客 iframe 引用。** 默认没问题，但如果加了安全头，必须放行：

```nginx
# 不要用 X-Frame-Options: DENY / SAMEORIGIN
# 方案 B 同源嵌自己时通常不需要；方案 A 子域被博客嵌时再加：
add_header Content-Security-Policy "frame-ancestors https://www.yuanfang19959.icu";
```

**2. 关掉反代缓冲，否则流式会被攒成一坨再吐出来。** 方案 B 已在上面的 `/ui/` 与 API `location` 里写了 `proxy_buffering off`。后端也带了 `X-Accel-Buffering: no`，显式配上更稳。

**3. 先构建前端再用 pm2 起后端。** 静态目录是在应用启动时挂载的；改前端后必须 `pnpm build` 再 `pm2 restart rag`：

```bash
cd /root/RAG/frontend && pnpm install && pnpm build   # 产物到 ../static/ui
cd /root/RAG && pm2 restart rag
```

**4. 公开到互联网前必须做的（P4）：** 现在 `/chat/stream` 谁都能调，直接烧的是你的 DeepSeek 额度。上线前至少要有 IP 限流，最好复用博客的 JWT 做鉴权。
