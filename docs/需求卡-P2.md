# 需求卡：P2 检索 + 非流式问答

## 1. 一句话需求

用户提一个问题，系统从 `chunks` 里找出最相关的几块内容，交给 DeepSeek 生成答案，并把引用的原文片段一起返回。

## 2. 本期做 / 不做

### 做

- 检索服务：问题向量化 → pgvector 余弦距离 → Top-K
- `GET /search`：只检索不调 LLM（调试用，能单独验证检索质量）
- `POST /chat`：非流式问答，返回 `answer` + `citations`
- prompt 约束：只依据检索到的资料回答，没有就承认不知道
- 知识库为空时直接返回提示，不浪费一次 LLM 调用

### 不做

- 流式输出（P3）
- 会话历史、多轮追问（P3）
- rerank、混合检索（关键词 + 向量）
- 鉴权（P4）

## 3. 成功标准（可验收）

- [x] 入库一篇文档后，`POST /chat` 能基于该文档内容回答（约 2.7 秒）
- [x] `citations` 能对上原文块（标题、序号、片段、相似度）
- [x] `GET /search` 单独可用，相关问题排在前面（Top1 score 0.67）
- [x] 问一个资料里完全没有的问题，回答「资料里没有提到这一点」
- [x] 知识库为空时返回提示且不调 LLM（0.37 秒返回）
- [x] 参数非法返回 422（空问题、`top_k` 超范围）
- [ ] 未配置 LLM key 时返回 503（代码路径与 embedding 的 503 一致，未单独跑）

### 踩坑记录

curl 传中文查询参数要用 `--data-urlencode`，否则编码被破坏、检索结果明显变差（同一问题 score 从 0.67 掉到 0.44）。

## 4. API 契约

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/search?q=...&top_k=5` | 只做向量检索，返回命中片段 |
| POST | `/chat` | 检索 + 生成，返回答案与引用 |

### POST /chat 请求

```json
{ "question": "这个项目用什么数据库？", "top_k": 5 }
```

### 响应

```json
{
  "answer": "用 PostgreSQL 16 配合 pgvector……",
  "citations": [
    {
      "chunk_id": "...",
      "document_id": "...",
      "document_title": "README.md",
      "chunk_index": 2,
      "content": "库：rag_db（PostgreSQL + pgvector）……",
      "score": 0.82
    }
  ],
  "model": "deepseek-chat"
}
```

`score` 是余弦相似度（`1 - 余弦距离`），越大越相关。

### 错误码

| HTTP | 场景 |
|------|------|
| 422 | 问题为空或超长（FastAPI 自动校验） |
| 502 | LLM 调用失败 / 超时 |
| 503 | 未配置 embedding 或 LLM key，或数据库不可用 |

## 5. 主流程

1. 问题文本 → `aembed_query` 得到 1024 维向量
2. SQL：`chunks` join `documents`，只取 `status='ready'` 的文档，按余弦距离升序取 Top-K
3. 把命中片段编号拼成上下文（`[1] 标题：正文`）
4. 系统提示 + 上下文 + 问题 → DeepSeek
5. 返回答案与 `citations`

## 6. 技术要点

pgvector 的余弦距离在 SQLAlchemy 里用 `Chunk.embedding.cosine_distance(vec)`，对应 SQL 的 `<=>`。距离范围 0~2，越小越像，所以 `order_by(distance)` 升序。

HNSW 索引（P1 已建）走的就是 `vector_cosine_ops`，和这里的距离函数必须一致，否则用不上索引。

LLM 用 `langchain-openai` 的 `ChatOpenAI`，`base_url` 指向 DeepSeek，模型 `deepseek-chat`。

## 7. 失败与边界

| 场景 | 预期行为 |
|------|----------|
| 库里一条 ready 的块都没有 | 返回「知识库还没有内容」，`citations` 为空，不调 LLM |
| 检索到的片段相似度都很低 | 照常调 LLM，但 prompt 要求它承认资料不足 |
| LLM 超时或报错 | 502 并带原因 |
| `top_k` 超范围 | 422（限制 1~20） |

## 8. 非功能

- 一次问答两次网络调用（embedding + LLM），耗时秒级，P3 用流式改善体感
- LLM 超时设 60 秒
- `temperature` 设低一点（0.3），减少胡编

## 9. 联调

```bash
# 先确保有数据
curl -s -F "file=@README.md" http://127.0.0.1:8000/documents
curl -s -X POST http://127.0.0.1:8000/documents/<id>/ingest

# 只看检索
curl -s "http://127.0.0.1:8000/search?q=这个项目用什么数据库"

# 完整问答
curl -s -X POST http://127.0.0.1:8000/chat \
  -H 'Content-Type: application/json' \
  -d '{"question":"这个项目用什么数据库？"}'
```
