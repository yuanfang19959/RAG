## RAG P0 实例：服务骨架可跑通

> 目标：先有一个能起、能探活、能给后续接口挂载的 FastAPI 底座。  
> 对应规划阶段：**P0 骨架**（不做向量、不做 LLM）。

### 1. 一句话需求

开发者在本机启动 RAG 服务后，能通过 `GET /health` 确认服务与数据库配置就绪，为后续文档入库与问答接口打底。

### 2. 本期做 / 不做

#### 做

- FastAPI 应用入口与项目目录分层（`api` / `db` / 配置）
- `GET /health`（进程存活；可选探测 Postgres 连通）
- CORS（方便以后前端 / Electron 跨域）
- `.env` 读取（`DATABASE_URL` 等，密钥不入库）
- 创建 Postgres 库 `rag_db`（表可下期再建）
- README 补充：如何 `uv sync` / `uv run` 启动

#### 不做

- 上传文档、切块、embedding
- `/chat`、流式 SSE
- 鉴权 / JWT
- 接 PageIo / local-agent
- 装复杂前端（最多一个静态探活说明）

### 3. 角色与入口

| 角色 | 怎么进来 | 备注 |
|------|----------|------|
| 开发者本人 | curl / 浏览器 | 主验收方 |
| RAG 调试前端 | 暂无 | P1+ |
| PageIo | 不接 | P4 |
| local-agent | 不接 | P4 |

### 4. 成功标准（可验收）

- [x] `uv sync` 后依赖安装成功
- [x] `uv run` 启动服务，监听如 `http://127.0.0.1:8000`
- [x] `curl http://127.0.0.1:8000/health` 返回 JSON，含 `"status":"ok"`
- [x] 若配置了 `DATABASE_URL`，health 中能反映 DB 连通（`db: ok` / `db: error`）
- [x] 仓库内无明文 API Key / DB 密码提交（使用 `.env` + `.gitignore`）

### 5. 数据设计

#### 新库 / 改表

- **库名**：`rag_db`（PostgreSQL 16，本机已有）
- **扩展**：`pgvector`（本机若未装：`brew install pgvector`，再在库内 `CREATE EXTENSION vector;`）
- **本期表**：可不建表；P1 再建 `documents` / `chunks` 等

#### 与现有库边界

| 库 | 动作 |
|----|------|
| MySQL `blog_db` | 不动 |
| Postgres `langchain_db` | 不动（学习用 checkpoint） |
| Postgres `rag_db` | 新建，专给本项目 |

### 6. API 契约

| 方法 | 路径 | 说明 | 鉴权 |
|------|------|------|------|
| GET | `/health` | 探活 | 否 |
| GET | `/` | 可选：服务简介 + 后续接口列表 | 否 |

#### 响应示例

```json
{
  "status": "ok",
  "service": "rag",
  "version": "0.1.0",
  "db": "ok"
}
```

DB 未配置或连不上时仍可返回 200（方便先起服务），但 `"db": "error"` 并带简短原因；或约定 DB 失败返回 503——**P0 选定一种并写进 README**。

推荐 P0：**进程 ok 即 200，db 字段单独标状态**（前端转型学习时更直观）。

#### 错误码约定（全项目沿用）

| HTTP | 含义 |
|------|------|
| 400 | 参数错误 |
| 404 | 资源不存在 |
| 503 | 依赖不可用（可选） |
| 500 | 未预期错误 |

### 7. 主流程（Happy Path）

1. 安装 / 确认 Postgres，创建 `rag_db`
2. 配置 `.env` 中 `DATABASE_URL`
3. `uv sync` → 启动 FastAPI
4. 请求 `/health` → 看到 `status: ok`

### 8. 失败与边界

| 场景 | 预期行为 |
|------|----------|
| 未配置 `DATABASE_URL` | 服务能起；health 里 `db: skipped` 或 `not_configured` |
| Postgres 未启动 | 服务能起；health 里 `db: error` |
| 端口被占用 | 启动失败，终端报错（换端口或杀进程） |

### 9. 非功能（本期最低要求）

- **日志**：请求 path / 耗时（可用 FastAPI 中间件或默认 uvicorn 日志）
- **超时**：暂无
- **鉴权**：不需要
- **密钥**：仅 `.env`，加入 `.gitignore`

### 10. 分期与依赖

| 阶段 | 交付 | 依赖 / 风险 |
|------|------|-------------|
| **P0（本期）** | 可启动 + `/health` + `rag_db` | 需安装 pgvector（可放到 P1 前） |
| P1 | 上传 / 切块 / embedding / `documents`+`chunks` | LLM 或 embedding API Key |
| P2 | 非流式 `/chat` + citations | 同上 |
| P3 | SSE `/chat/stream` | 前端要会读流 |
| P4 | PageIo / local-agent 接入 | API 契约稳定 |

### 11. 联调方式

```bash
# 依赖
cd /Users/zhengzhibin/Desktop/RAG
source "$HOME/.local/bin/env"   # 若 uv 不在 PATH
uv sync

# 启动（P0 落地后的预期命令，实现时可微调）
uv run uvicorn rag.main:app --reload --port 8000

# 探活
curl -s http://127.0.0.1:8000/health | jq
```

## 怎么用这张卡（前端转后端备忘）

1. **先填「做 / 不做」和「成功标准」**——这两栏最能防止做到一半飘走。  
2. **再填表结构和 API**——相当于后端的设计稿。  
3. **开发只服务「成功标准」勾选**——勾完就合并 / 演示，再开下一张卡（P1）。  
4. 需求变更时：**改卡，不偷偷加功能**——新想法写进「下期」或新开一张卡。
